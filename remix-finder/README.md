# リミックス楽曲ファインダー

リミックス動画（マッシュアップ／sped up・slowed などの加工版／DJリミックス）をアップロードすると、

- **原曲**（ボーカル側の曲）
- **ビートの元ネタ**（伴奏側の曲）

を探し、Apple Music と Spotify のリンクを表示する、自分用のアプリです。自分の PC の中だけで動きます（インターネットに公開はしません）。

---

## 使い方

1. このフォルダ（`remix-finder`）の中の **`start.bat` をダブルクリック**します。
2. 黒い画面（コマンドプロンプト）が開き、少しするとブラウザで画面が開きます。
   開かないときは、ブラウザで `http://localhost:8765` を開いてください。
3. 「ここをクリックして動画を選ぶ」から動画（mp4 など）を選び、「解析する」を押します。
4. 解析が終わると、「原曲（ボーカル）」と「ビート」のカードに曲名とリンクが出ます。
5. 終わるときは、黒い画面を閉じます。

### はじめて起動するとき

`start.bat` が必要なものを自動で用意します。

| 用意するもの | 何をするものか |
|---|---|
| uv | Python（プログラムを動かす土台）とライブラリをまとめて入れてくれる道具 |
| ffmpeg | 動画から音声を取り出す道具 |
| Demucs | 音声を「ボーカル」と「それ以外（ビート）」に分ける AI |

- uv や ffmpeg を入れた直後は「もう一度 start.bat をダブルクリックしてください」と表示されます。言われた通りにもう一度起動してください。
- 初回はライブラリのダウンロード（合計 1GB 弱）があるため、10分ほどかかることがあります。
- 最初に動画を解析するときは、Demucs の AI モデル（約 80MB）のダウンロードもあります。

## AudD（曲を判定するサービス）の APIキーの設定

最初は **ダミーモード** になっています。ダミーモードでは AudD を呼ばずに「ダミー原曲」「ダミービート」という試し用の結果を出すので、回数を消費しません。

本当に曲を探すには、次の手順で APIキー（AudD を使うための合言葉のような文字列）を設定します。

1. <https://dashboard.audd.io/> でアカウントを作り、表示される **API Token** をコピーします。
2. このフォルダの **`.env`** ファイルをメモ帳で開きます（最初の起動で自動的に作られます）。
3. 次のように書き換えて保存します。

   ```
   AUDD_API_TOKEN=ここにコピーしたトークン
   AUDD_MODE=real
   ```

4. 黒い画面を閉じて、`start.bat` を起動し直します。画面上部が「本番モード」になっていれば OK です。

> `.env` は秘密の情報を入れるファイルです。人に渡したり、GitHub に上げたりしないでください（自動で除外される設定にしてあります）。

## 回数の使いすぎ防止

AudD の無料枠は回数と期限が限られているので、次の仕組みを入れています。

- **1本あたりの上限**：`settings.ini` の `max_requests_per_video`（最初は 30 回）。上限に達したらそこで止めます。
- **キャッシュ**：同じ動画の同じ場所の結果は `cache` フォルダに保存し、もう一度解析しても AudD には問い合わせません。
- **無音のスキップ**：ボーカルが入っていない部分など、ほぼ無音のところは送りません。
- **回数の表示**：結果画面の下と黒い画面に「今回使ったリクエスト数」と「これまでの累計」が出ます。

## 解析のしくみ

1. 動画から音声を取り出す
2. **そのまま認識**：音声を一定間隔（最初は 20 秒ごと）で 12 秒ずつ切り出して AudD に問い合わせる
3. **分離して認識**：Demucs でボーカルとビートに分け、それぞれ同じように問い合わせる
4. **速度補正して認識**：まだ見つかっていない側を、速度を何段階か変えて問い合わせる
   - sped up / slowed は速度と音の高さが一緒に変わっていることが多いので、「サンプリングレート（1秒あたりの音の細かさ）の読み替え」で速度と高さを同時に元に戻しています。
5. 結果をまとめて表示する

結果には「どの方法で見つかったか（そのまま／分離後／速度補正後）」と「動画内のおおよその位置」も出ます。

## 設定（settings.ini）

メモ帳で開いて数字を変え、アプリを起動し直すと反映されます。

| 項目 | 意味 | 最初の値 |
|---|---|---|
| `clip_seconds` | 1回に送る長さ（秒） | 12 |
| `interval_seconds` | 何秒ごとに切り出すか | 20 |
| `max_requests_per_video` | 1本あたりの AudD の上限回数 | 30 |
| `speed_factors` | 速度補正で試す倍率（左から順に試す） | 1.25, 0.8, 1.2, … |
| `speed_probe_clips` | 1つの倍率につき何か所試すか | 2 |
| `silence_threshold_db` | これより静かなところは送らない | -45 |
| `demucs_model` | 分離に使う AI モデル | htdemucs |
| `port` | 画面のアドレスの番号 | 8765 |

### 速度補正の倍率について

`speed_factors` の数字は「動画が元の曲の何倍速になっているか」の予想です。

- `1.25` … 1.25 倍速の sped up 版（音が高く・速い）
- `0.8` … 0.8 倍速の slowed 版（音が低く・遅い）

よく見る動画に合わせて、よく当たる倍率を左に並べると回数を節約できます。

## 著作権と後片付け

- アップロードした動画と、分離したボーカル・ビートの音声は、解析にだけ使い、**解析が終わったらすぐ削除**します（`work` フォルダは空になります）。
- 分離した音声をダウンロードする機能はありません。

---

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 「winget が見つかりません」と出る | Microsoft Store で「アプリ インストーラー」をインストールしてから、もう一度起動 |
| 「ffmpeg が見つかりません」と出る | 黒い画面を閉じて `start.bat` を起動し直す |
| 「AudD エラー 900」 | APIキーが間違っています。`.env` を確認 |
| 「AudD エラー 901 / 902」 | 無料枠の回数を使い切った可能性があります。AudD のダッシュボードで確認 |
| 分離にとても時間がかかる | GPU がない PC では、3分の曲で数分かかります。そのまま待ってください |
| 画面が開かない | ブラウザで `http://localhost:8765` を開く |

## 開発者向けメモ

- 構成：Python 3.12 / FastAPI / ffmpeg / Demucs 4.1.0（`adefossez/demucs` の PyPI 版）/ AudD API
- テスト（AudD を呼びません）：`uv run pytest`
- Demucs を動かさずに流れだけ試す：環境変数 `REMIX_FINDER_FAKE_SEPARATION=1` を付けて起動
- ファイル構成
  - `app/main.py` … Webサーバー（アップロード受付・進み具合の返却・後片付け）
  - `app/pipeline.py` … 解析の流れと結果のまとめ
  - `app/audio.py` … ffmpeg での音声の取り出し・切り出し・速度補正
  - `app/separate.py` … Demucs での分離
  - `app/audd.py` … AudD の呼び出し・キャッシュ・回数上限・ダミー応答
  - `app/static/index.html` … 画面
